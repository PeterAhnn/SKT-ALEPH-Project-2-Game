# 과제 2 — 내가 설계한 미니게임

사용자가 전달한 전체 과제 설명·카드 1~5. 계획시간 6~7h. 입력·상태·검사 기록으로 난이도를 조정하는 브라우저 게임입니다.
전체 과정 매뉴얼: https://aleph-omega.vercel.app/manual/student-free (이번 세션에서 전문 열람 불가).

## 사용자 설계

IT 소재 뱀서라이크, 체크 셔츠·뿔테안경 개발자, 공식 언어 로고 및 장비 아이콘.
WASD/방향키 이동, 자동 공격. 30초 생존 성공/체력 0 실패는 AI 제안을 수락한 구성입니다.
스테이지: ① 별 것도 아닌 일에 “어~?” 금지 ② 3인 이상 모여있기 금지 ③ “한가롭네, 평화롭네” 금지.
이전 스테이지 성공 후 다음 해금/이동. 일시정지 화면에 이어하기/처음으로 돌아가기.
소스는 GitHub 공개 저장소, 배포는 Vercel을 사용합니다.

## 제출물

무로그인 공개 게임 URL / 공개 소스 URL / 확인법 4줄(위치·3단계 이내 행동·통과 모습·안 될 때 모습) / 판단 3줄(AI에게 맡긴 일·학생 직접 판단·AI 제안을 따르지 않은 일 또는 없었던 이유).
검사 증거는 보관하되 제출에는 위 주소와 설명만 남깁니다.

## 카드 1 — 30초 핵심 규칙

- T02-C01: 모든 URL은 새 시크릿 창에서 계정 생성·로그인·인증·초대·비밀번호·OAuth·CAPTCHA 없이 열림.
- C03~05: 규칙·핵심 조작·현재 상태 공개 화면 표시.
- C06: 입력 한 번이 상태 변화 한 번으로 반영.
- C07: 시작 후 30초 안에 성공 또는 실패 도달 가능.
- C08~09: 성공/실패 후 재시작은 현재 판 초기화.

원문에 C02는 없으므로 임의로 추가하지 않습니다. 시작·진행·종료·재시작 증거를 남깁니다.

## 카드 2 — PC 경계 검사

- C10~11: 1366×768 / 1920×1080에서 조작 영역 잘림·가로 넘침 0건.
- C12: 1초 안에 같은 핵심 입력 10건, 이벤트당 정확히 1회 반영.
- C13~14: 창 크기 변경·포커스 이탈/복귀 후 상태·조작 유지.
- C15: 정지 중 진행 없음, 재개 후 이어짐.
- C16~17: 실제 10분 연속 실행 후 조작 가능·브라우저 콘솔 빨간 오류 0건.

검사 전 예상값 작성. PC 검사표와 10분 콘솔 결과 보관.

## 카드 3 — 10회 전후 난이도 선택

- C18~19: 변경 전 동일 설정 10회, 변경 후 동일 설정 10회.
- C20: 두 묶음 사이 난이도 값 하나만 변경.
- C21: 범위·중앙값 또는 반복 실패 원인에 연결된 최종 선택 이유.

같은 스테이지·게임 버전·조건에서 A=0.8초/B=0.6초 생성 간격만 변경합니다. 점수·시간·실패 원인 20회 표와 선택 이유 보관.

## 카드 4 — 저장과 손상 복구

- C22: 새 게임 현재 판 초기화.
- C23: 선언한 기록 재접속 후 보존.
- C24~25: 빈 값·손상값에서 중단 없이 선언한 기본값으로 복구.

초기화/보존 값과 기본값은 dist/README.md 참고. 정상·빈 값·손상값에서 새 판/재접속 결과 보관.

## 카드 5 — 효과와 선택권

- C26: 효과는 선언한 사건(성공)에서만 실행.
- C27: 움직임 줄이기를 켜면 해당 효과 즉시 감소/정지.
- C28: 공개 화면·제출물 개인정보 0건.
- C29: 공개 화면·배포 파일·제출물 비밀값 원문 0건.
- C30~31: 확인법 4항목과 AI/학생 판단 3항목 구분.
