# [과제 번호] · [과제명] 제출 입력 문안

## 결과물 URL (필수)

[무로그인 공개 HTTPS 결과물 URL]

`https://`로 시작하는 실제 공개 결과물 주소를 입력한다.
제출하는 모든 URL은 계정 생성·로그인·인증·초대·비밀번호·OAuth·CAPTCHA 없이 새 시크릿 창에서 열려야 합니다.
결과물 URL과 소스 URL을 모두 확인하며, 미확인 상태를 검증 완료로 기재하지 않는다. 과제별 명시적 예외는 해당 제출 기준을 따른다.

## 소스 저장소 URL

https://github.com/OWNER/REPO/commit/FULL_COMMIT

실제 저장소에서 확인한 40자리 또는 64자리 소문자 전체 커밋 해시로 FULL_COMMIT을 교체한다. 저장소 첫 화면, 브랜치 주소, 짧은 해시, `/tree/` 주소로 대체하지 않는다.

## 재현·통과 확인 4가지

```text
어디로 가나요: [공개 결과물 URL 또는 파일 안의 정확한 위치]
무엇을 하나요(3단계 이내): 1) [첫 행동] 2) [두 번째 행동] 3) [세 번째 행동]
무엇이 보이면 통과: [눈으로 확인할 수 있는 구체적인 기대 결과]
안 될 때: [오류·빈 상태의 모습과 실제 가능한 복구 방법. 정상 상태와 오류를 구분]
```

## AI와 내 판단 3줄

```text
AI에게 맡긴 일: [AI에게 맡긴 실제 작업]
내가 판단한 일: [사용자가 직접 선택하거나 결정한 내용]
AI 말을 안 들은 일: [따르지 않은 제안과 대신 선택한 내용. 없으면 없었던 실제 이유]
```

## 선택 확인 파일

[첨부할 실제 검사 근거의 파일명 또는 첨부 없음]

T02는 결과물 URL과 소스 저장소 URL이 모두 필수이며 확인 파일은 선택이다. 다른 과제의 필수 항목·개수·형식·예외는 해당 과제의 제출 화면을 확인한다.

## 제출 전 확인 — 제출 입력란과 구분해 관리

- 예시·대괄호·OWNER·REPO·FULL_COMMIT을 실제 값으로 교체한다.
- 공개 접근이 요구되는 모든 URL을 새 시크릿 창에서 확인한다.
- 제출 소스 커밋과 검증한 배포의 코드가 일치하는지 확인한다. 새 코드 배포 시 고정 URL도 갱신한다.
- 확인 4가지와 판단 3줄을 각각 1,500자 이내로 작성한다.
- 과제별 실제 검사·플레이·사용자 판단의 미완료 항목을 기록한다. 제출 가능과 과제 완주는 구분한다.
- 개인정보·비밀값이 공개 파일과 제출 문안에 없는지 확인한다.
