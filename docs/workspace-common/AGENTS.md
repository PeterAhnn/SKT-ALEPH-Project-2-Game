# SKT ALEPH 공통 작업 지침

- 과제 시작 시 이 폴더의 `SKT-ALEPH-project-guide.md`와 해당 과제의 상세 기준·인수인계 문서를 읽는다.
- 제출 문안은 `ALEPH-SUBMISSION-TEMPLATE.md`를 기준으로 해당 과제의 `docs/SUBMISSION.md`에 작성한다.
- 사용자가 확정한 제출 항목명과 URL 형식을 유지한다. GitHub 소스 URL은 `https://github.com/OWNER/REPO/commit/FULL_COMMIT` 형식이며 실제 확인한 40자리 또는 64자리 소문자 전체 커밋 해시를 사용한다.
- `결과물 URL (필수)`은 공개 HTTPS 주소로 작성한다. 제출하는 모든 URL은 계정 생성·로그인·인증·초대·비밀번호·OAuth·CAPTCHA 없이 새 시크릿 창에서 열리는지 확인한다. 명시적 과제별 예외만 해당 기준에 따른다.
- 확인 항목은 `어디로 가나요`, `무엇을 하나요(3단계 이내)`, `무엇이 보이면 통과`, `안 될 때` 네 가지이다.
- 판단 항목은 `AI에게 맡긴 일`, `내가 판단한 일`, `AI 말을 안 들은 일` 세 줄이다. 마지막 항목이 없으면 실제 이유를 적는다.
- 실제 검증·플레이 기록·사용자 판단을 만들지 않는다. 미완료 항목을 별도로 표시한다.
- 과제별 제출 필수값·예외는 해당 과제의 최신 화면을 따른다. T02에서 결과물 URL과 소스 URL은 모두 필수이고 확인 파일은 선택이다.
- 공통 형식 변경 시 가이드와 템플릿을 함께 수정하고 해당 과제의 제출 문안에 반영한다. 과제별 가이드 사본은 고유 내용을 보존하며 공통 제출 규칙을 동기화한다.
- 웹 브라우징은 gstack `/browse` 스킬을 사용한다. `mcp__claude-in-chrome__*` 도구를 사용하지 않는다.
